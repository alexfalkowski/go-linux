## Resource model and caller

The caller creates `epoll.New()`, registers a standard `*os.File` through `poller.Add(file, interests)`, waits into a caller-owned `[]epoll.Event`, and closes each `*epoll.Registration` or the whole `*epoll.Poller`. `registration.Modify(interests)` replaces the entire mask and rearms one-shot delivery. Both owners implement `io.Closer`; byte I/O interfaces do not fit a readiness set. A registration pointer is the public event identity. Files and raw descriptors stay private.

The package depends only on the standard library and the pinned `x/sys/unix`. Existing facility packages do not depend on epoll. This initial API accepts standard files, including pipe ends and independently supplied socket files; integration with opaque Counter, Timer, and Process owners is omitted rather than adding raw access or a universal descriptor interface. Poller keeps direct private files for its instance and wakeup; each Registration keeps its own private duplicate. The per-instance map translates kernel tokens to registration owners; it is not a shared resource registry or descriptor accessor.

## Included operations and identity

| Surface | Linux operation and contract |
| --- | --- |
| `New` | `epoll_create1(EPOLL_CLOEXEC)`, nonblocking close-on-exec `eventfd2`, and a private level-triggered wake registration |
| `Add` | Protected `F_DUPFD_CLOEXEC` of a borrowed file followed by `EPOLL_CTL_ADD`; owns failure cleanup |
| `Registration.Modify` | `EPOLL_CTL_MOD` with the full mask and unchanged identity; rearms one-shot delivery |
| `Registration.Close` | `EPOLL_CTL_DEL` followed by close of the private duplicate |
| `Wait` | Baseline epoll waiting, preserving returned condition bits and translating stable registration identities |
| `Poller.Close` | Mark closed, signal all waiters, join waits, and release instance, wake file, and remaining duplicates |

`Events` is a typed Linux mask. Readable, Writable, Priority, ReadHangup, Error, and Hangup preserve Linux conditions. LevelTriggered is zero, EdgeTriggered requests EPOLLET, and OneShot requests EPOLLONESHOT. Unknown input bits fail with `os.ErrInvalid`. Zero interests are meaningful: Linux still reports Error and Hangup. Returned kernel bits are preserved, including any unknown output bits; control flags are not synthesized as results. Linux validates source support, preserving EPERM for ordinary disk files. Readiness remains advisory, with no reservation of I/O or guaranteed event count or ordering.

Every successful Add owns a separate duplicate and therefore a separate kernel registration even for the same source. Closing the borrowed source cannot invalidate that duplicate, retarget it to a reused descriptor, or implicitly remove the registration. This extends the open-file-description lifetime and can delay pipe EOF or socket teardown; callers must close registrations. File status flags and source deadlines are unchanged. The duplicate shares offsets and other open-file-description state, though epoll never reads or writes it.

Kernel data holds a monotonically increasing nonzero 64-bit token, split across the maintained x/sys EpollEvent Fd/Pad data fields and recombined without pointer storage, unsafe ABI casting, or descriptor interpretation. This works with the different amd64 and arm64 event layouts because x/sys owns those layouts. Token zero belongs to the wake entry. Tokens are never recycled, including after removal; exhaustion returns EOVERFLOW before acquisition. Wait drops tokens whose registrations have been removed. A batch translated before removal may still return its original registration pointer; it can never identify a replacement. Modify does not invalidate previously returned readiness.

## Ownership, concurrency, and waiting

Add borrows a source only during the call, duplicates under `RawConn.Control`, and closes its duplicate if registration fails. New returns nil and closes all acquisitions on failure. No error-path resource cleanup is assigned to callers. Registration deletion errors retain ownership for retry; after successful deletion, the duplicate is attempted once and the registration remains closed even if close fails. Poller.Close attempts every owned close once and joins errors. Source files remain caller-owned throughout.

One mutex serializes lifecycle transitions, kernel control operations, and result translation. It is never held across an epoll wait. A wait group pins the complete poller lifetime between wait admission and return; Close prevents new admission before waiting for existing callers. Close writes one eventfd record and leaves it unread with level triggering so concurrent waiters all observe shutdown. Instance and wake files remain open until every waiter has left, eliminating close/reuse races inside epoll_wait. Source duplicates remain protected by the control mutex. RawConn callbacks protect descriptor access through supported Go interfaces; no private runtime hooks are used.

Negative timeouts wait indefinitely, zero polls immediately, and positive durations subtract elapsed Go monotonic time from the original budget. This preserves monotonic measurement even for MaxInt64 durations, where adding a future deadline could overflow time.Time's monotonic component. Millisecond conversion rounds up without overflow and clamps each syscall to a signed-32-bit timeout; longer waits and EINTR retries recompute the remaining duration. Expiration returns `(0, nil)` and leaves the result buffer untouched. Empty or Linux-oversized result buffers are invalid before state checks. Source deadlines do not control epoll waiting. Close returns `os.ErrClosed` to every pending Wait, though already translated results may succeed. Multiple waiters compete for events, including one-shot delivery; the API does not broadcast source events.

An explicit wait can occupy an OS thread. There is no goroutine per poller and no context, signal-mask manipulation, or general Interrupt method. Close and per-call timeout are the supported interruption mechanisms. The pinned EpollWait wrapper invokes epoll_pwait with no signal mask on both target architectures; this predates the selected Linux 7.0 floor. Newer epoll_pwait2, busy polling, EPOLLWAKEUP, EPOLLEXCLUSIVE, nested-instance integration, raw adoption/export, and opaque producer integration are omitted. Go's runtime network poller remains responsible for normal Go I/O.

Zero owners report `os.ErrInvalid`; removed/closed owners report `os.ErrClosed`, including Go's otherwise private RawConn closing errors on borrowed sources. Nil receivers are unsupported. Owners must not be copied after use. Input validation precedes closed state for nil files, unknown flags, and invalid result buffers. Errors retain their syscall errno through wrapping; readiness Error is separate from a Wait failure.

## Verification and prerequisites

Ordinary coverage uses external Go tests with require assertions and the shared `package=epoll make specs` race/coverage/JSON/JUnit harness. Real pipes verify level/edge delivery, one-shot suppression and rearming, mask replacement, multiple identities, writable readiness, automatic HUP/ERR, addition/input wakeups, finite and long timeout handling, concurrent shutdown, removal, and source lifetime including EOF after removal. Focused ABI cases independently observe socket priority and half-close conditions, close-on-exec/nonblocking flags, actual source descriptor reuse, unchanged source flags/deadlines, and complete resource release through procfs. Resource-exhaustion subprocesses lower only their own RLIMIT_NOFILE to verify epoll/wake/duplicate acquisition failure cleanup. Local Go 1.27.0 and 1.27.4 runs each pass all 41 test events without skips; package statement coverage is 88.6% at Go 1.27.4 (91.1% at Go 1.27.0). Primary-target runtime verification is also complete at 5e42c6f through jobs 236/238; the local coverage percentages describe the local runs.

Prerequisites are permitted epoll creation/control/wait, eventfd creation/write, fcntl duplication, pipe and local Unix-stream I/O, procfs, and bounded subprocesses. The priority-event fixture needs CONFIG_AF_UNIX_OOB: an observed sendmsg(MSG_OOB) EOPNOTSUPP skips only that scenario on optional runs and fails required=true runs. Other unexpected syscall errors fail. No shared host settings are changed. Rare epoll_ctl allocation/deletion errors, eventfd-write failures, a literal 64-bit token wrap, waits spanning weeks, and deterministic signal-induced EINTR remain source-reviewed paths rather than injected private seams. Concurrency tests sample real schedules without proving every interleaving. There is no parser or performance promise warranting fuzzing or benchmarks.
