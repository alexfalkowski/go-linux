# mount design

P06 implements descriptor-based mount operations. [The usage guide](../mount.md) owns caller workflows and [the plan](../../IMPLEMENTATION.md) owns acceptance. P06 is complete for the observed Linux 7.0 arm64 target: required isolated [Go 1.27.0 job 195](https://circleci.com/gh/alexfalkowski/go-linux/195) and [Go 1.27.4 job 192](https://circleci.com/gh/alexfalkowski/go-linux/192) each pass all 39 mount events without failures/skips at ae50d8d. Local namespace creation remains unavailable with EPERM; the accepted evidence comes from actual CI mount operations. Those reports predate the private-file refactor; its revised ABI setup still requires capable-runner execution.

## Caller and ownership model

The caller selects an isolated mount environment and filesystem, then calls `mount.Open("tmpfs")`, configures individual parameters, calls `Create`, obtains a detached `Handle` with `Mount`, changes attributes, attaches explicitly, and closes both owners. `Clone` acquires a detached copy independently. This follows the provisional [shared API design](api.md#p06-mount), with no new dependencies. Direct unexported file fields keep both owners opaque without an embedded holder or additional lifecycle state. This is a local Go API with no HTTP transport or wire contract.

Config and Handle each privately own one `*os.File`, exposing typed methods and Close without raw access or ordinary stream methods. Every acquisition uses the kernel close-on-exec flag and returns nil on error. No fallible setup follows successful descriptor acquisition. Config.Mount borrows the configuration descriptor; Clone and Attach borrow a caller's directory. A private package-local protected-Control helper centralizes descriptor lifetime/error normalization for both owners and directory borrowing. It does not duplicate descriptors, take directory ownership, or change status flags. Go RawConn.Control fails before calling the callback when lifetime acquisition fails and returns nil after a completed callback; no acquired result can be stranded by a later Control error in this path.

There is no Adopt: no current caller requires validating arbitrary filesystem-context or mount descriptors. No independent finalizer/state cache/closed boolean is needed beyond os.File lifetime management. Config has a mutex because configuration operations and their diagnostic reads must not interleave. Handle operations use os.File's protected raw access, with kernel serialization and no mirrored mount state. A failed operation on an existing owner leaves it caller-owned, even when the kernel changes phase or partially applies attributes. Closing an attached handle releases only the descriptor and never promises unmount. Config.Close cannot invalidate previously acquired mount handles.

## Bounded surface

| Public operation | Selected Linux mechanism |
| --- | --- |
| Open | fsopen with FSOPEN_CLOEXEC |
| SetFlag / SetString | FSCONFIG_SET_FLAG / FSCONFIG_SET_STRING; retain flag versus empty string distinction |
| Create | FSCONFIG_CMD_CREATE; explicit, possibly reusing a superblock |
| Mount | fsmount with FSMOUNT_CLOEXEC and validated per-mount restrictions |
| Clone | open_tree with OPEN_TREE_CLONE, OPEN_TREE_CLOEXEC, optional AT_RECURSIVE, and AT_EMPTY_PATH for an explicit directory |
| SetAttributes | mount_setattr with AT_EMPTY_PATH, optional AT_RECURSIVE, and only Attr_set/Attr_clr populated |
| Attach | move_mount from descriptor/empty path, adding target-empty-path only for an explicit target directory |
| Diagnostics | read complete filesystem-context records until ENODATA, retrying EINTR |
| Stat / Attributes | Standard root metadata and an fstatfs snapshot filtered to the four supported restrictions |
| Unmount | umount2 with zero flags or MNT_DETACH; preserve reference ownership |

The initial four attribute bits are read-only, nosuid, nodev, and noexec. Zero masks add/change nothing; clearing restrictions requires an explicit clear mask. Unknown bits and overlapping masks match os.ErrInvalid. Filesystem validation is kernel-owned, including the 255-byte fsconfig key/string limits and phase transitions. Errors retain errno identity through standard PathError/SyscallError wrappers. No automatic retries of state-changing operations are added; EINTR is preserved there because retry/phase consequences are operation-specific.

Path operations deliberately use native kernel lookup: nil directory means AT_FDCWD, absolute paths are absolute, and empty paths require an explicit directory. Clone follows open_tree defaults for symlinks and automounts, whereas Attach omits move_mount target-follow flags. No openat2-style confinement is implied. Binary/path/fd configuration values, reconfiguration/fspick, exclusive superblock creation, ID maps, atime groups, propagation changes, namespace creation flags, forced/expiry unmount modes, orchestration, and cancellation are omitted. A legacy mount call is used solely to make the integration fixture's isolated propagation private; production has no legacy backend and no namespace package is introduced before P15.

## Diagnostic evidence and sizing decision

The provisional sketch warned about destructive undersized reads. Inspection of the exact Linux 7.0 implementation refines that claim: fscontext_read checks the message length before advancing the queue, so EMSGSIZE retains that record. The producer now uses kasprintf without a fixed per-message bound; the eight-entry queue bounds record count, not message bytes. A fixed page-sized buffer cannot establish complete retrieval for every filesystem.

readDiagnostics therefore starts at 4 KiB and doubles on EMSGSIZE to a 1 MiB per-message allocation limit. At the limit it returns EMSGSIZE together with any earlier complete records. The current oversize record remains queued on the supported baseline. Other retrieval errors likewise preserve partial records. ENODATA means an empty queue and EINTR is retried. Framed records retain unknown severity values and omit only framing; malformed/unframed records, including allocation-failure fallback text, retain complete bytes. No promise of lossless logging or unlimited allocation is made.

Config methods serialize the syscall and automatic failure-drain in one critical section and one protected raw callback. A structured Error holds the primary SyscallError, partial Diagnostics, and a separate DiagnosticError. Unwrap exposes only the primary cause so errors.Is cannot confuse retrieval failure with operation failure. A successful operation leaves diagnostics available for explicit Diagnostics; consequently an error may include earlier success warnings. No public raw access can bypass this serialization. A focused ABI fixture fills the real diagnostic queue without draining to verify bounded ordering; ordinary scenarios use typed configuration methods. No pending-log cache, injection seam, or public logging callback is needed.

## Verification and challenge scope

Tests use the existing external Go test package, require assertions, gotestsum reports, and race-enabled package selector. Default tests execute zero-owner behavior, invalid masks/targets, NUL rejection, structured-error identity, real failed fsopen/open_tree errno parity, and failed-acquisition descriptor counts. They do not claim successful mounting.

The namespace profile runs each named integration behavior in its own bounded user/mount namespace subprocess with one-entry UID/GID mappings. Resource setup, subprocess handling, and isolation live in [internal/test](../../internal/test); behavior assertions remain in the mount tests. The child verifies its mount namespace differs, makes propagation private, then probes fsopen(tmpfs). Only precise known namespace creation/mapping or private-propagation/fsopen prerequisite denials can become optional skips. Required mode fails those prerequisites. All subsequent library-operation failures fail, including EPERM and EINVAL; successful namespace creation alone cannot pass an integration test. The parent checks that its own namespace identity is unchanged. Successful child output includes a completion marker after behavior and cleanup have run; nonzero status, missing marker, or a timeout fails the parent. Separate parent test names make verified and skipped behaviors visible in gotestsum's report.

Integration scenarios cover explicit configuration/creation, all sixteen attribute combinations, constructor attributes/zero defaults, phase errors, full error records, newest-eight queue order, concurrent per-operation diagnostics, concurrent Config.Close, empty/relative/absolute directory lookup, failed-attachment ownership, persistence after Handle.Close, recursive versus single cloning, recursive and nonrecursive attribute changes, independent clone restrictions, descriptor flags/counts, and EMFILE for all three acquisition paths. Descriptor exhaustion changes only the already isolated child's soft limit and restores it. Executable examples are invoked inside the same fixture; normal Go example discovery only compiles them because they have no unconditional Output expectation on an unprivileged runner.

The Docker CI Go matrix runs required rootless coverage. Its namespace creation succeeds, but private mount propagation returns EACCES. The separate required arm.medium machine matrix therefore runs the existing Go image as root in a privileged container while preserving the fixture's namespace isolation. At ae50d8d, jobs 195/192 execute package=mount make specs profile=namespaces required=true arch=arm64 at both Go versions on actual Linux 7.0.0-1004-aws arm64, with 39 passes and no failures/skips each. The separate Docker jobs 193/194 pass ordinary-user coverage on Linux 7.0.0-1017-aws. This verifies successful mount operations independently of namespace discovery and cross-compilation.

The first executable mount run exposed a test expecting ENAMETOOLONG for a 256-byte key. Linux 7.0 fsconfig calls strndup_user with a 256-byte bound including NUL; oversized input returns EINVAL. The expected value was corrected without changing production errno handling or subsequent context-usability assertions. The corrected required runs pass.

Challenge review checks ownership on every failed acquisition, protected callback completion, diagnostic errno separation, unknown/overlapping masks, private propagation before attachment, typed metadata/attribute snapshots, normal versus detached unmount references, recursive cloning and attribute scope, unmount-before-directory cleanup order, and required-profile failure. Oversize diagnostic growth, rare retrieval/allocation/close failures, malformed records, and exhaustive interrupted/concurrent schedules remain source-reviewed limitations beyond executed cases. Direct private file fields retain each owner's file; focused ABI fixtures discover newly acquired descriptors through procfs while keeping their owners open. No fake filesystem context or test-only public hook substitutes for kernel evidence. Confidence: 95% for P06 acceptance on the observed target. The separate Codecov project coverage gate remains unresolved; package runtime acceptance does not assert overall PR or release readiness.
