# Verification

This guide helps contributors run the library's checks and understand the environments they require. Use Linux 7.0+ and the Go version declared in [go.mod](../go.mod), with the [README setup](../README.md#-setup) completed. [Verification limits](verification-limits.md) records missing execution evidence; detailed results belong in CI reports.

## Run local checks

Discover commands with `make help`. The standard checks are:

```sh
make dep
make test-environment
make vet
make lint
make scripts-lint
make specs
make coverage
make sec
```

Run from the repository root. Install the quality tools listed in the README and ShellCheck for `scripts-lint`; missing tools are uncovered validation. Dependency setup and security scanners may download modules or databases. `make ci-validate` additionally requires the CircleCI CLI and API access.

Scope tests to the changed package, for example:

```sh
package=file make specs profile=rootless required=true arch=amd64
```

The gotestsum harness runs with race detection and coverage. Reports are written under `test/reports/`: `specs.json` retains test events and skips, `specs.xml` is JUnit, and `profile.cov` is the coverage input. `make coverage` creates `final.cov` and `coverage.html` from that run. A later test run replaces the reports, so retain any results you need before changing package or profile. CI stores each job's reports separately. Reexecuted fixtures assert operation results in the child; the parent coverage profile does not aggregate child statement counters.

Use the [shared thread helpers](../internal/test/thread.go) for thread-affine tests: `LockThread` pins the current goroutine for its remaining lifetime, and `LockedThread` runs a bounded worker. Executable examples show the public runtime calls. Irreversible mutation fixtures still require bounded subprocesses when using these helpers.

Cross-package examples run with their owning packages: select `package=memfd` for a shared mmap region, `package=eventfd` for counter readiness through epoll, and `package=timerfd` for expiration readiness through epoll. The counter/timer registration suites exercise nonconsuming readiness, one-shot rearming, independent source/registration/poller lifetimes, rejected-input cleanup, and registration racing source close. Their ordinary rootless runs do not change clocks; cancellation-readiness coverage runs in the [disposable-VM clock-change lane](#clock-changing-tests).

CI stages each raw profile with `make coverage-workspace-stage partition=<facility>-<arch>`, selecting `rootless`, `netlink`, `namespace`, `cgroup`, `mount`, `fanotify`, or `timerfd` and `arm64` or `amd64`. Each partition has its own directory under `/tmp/go-linux-reports`. After all fourteen jobs pass, the separate coverage job attaches that workspace and runs `make coverage-workspace-merge` followed by `make coverage`. Merging requires all fourteen nonempty atomic profiles from the same revision and uses `gocovmerge`, included in the Go image; missing inputs or incompatible profiles fail the job. The Netlink partition contains the single raw profile produced by testing both packages together. Only raw inputs are merged, and `make coverage` applies `.gocov` exclusions.

The coverage job retains the combined reports and uploads `final.cov` once through `make codecov-upload`; sync and release wait for this job, including the required cgroup matrix. The rootless, Netlink, namespace, and cgroup jobs explicitly request `kernel=7.0`, so a newer host kernel fails their baseline checks. The combined report records statements exercised across the matrix; individual job reports remain the evidence for each architecture and environment.

The inotify overflow fixture fills only its own instance queue and never changes host limits. It bounds generation at `max_queued_events <= 65536`; a larger existing host limit skips the fixture in optional mode and fails with `required=true`. Decoder fixtures still cover the overflow record independently.

The socket backpressure fixture fills only a test-owned Unix datagram endpoint, using the existing `/proc/sys/net/unix/max_dgram_qlen` value without changing it. Limits above 65536 skip optional coverage and fail with `required=true`; bounded native producers distinguish destination-queue exhaustion from a single sender's buffer limit.

The eventfd, timerfd, inotify, and socket constructor suites use bounded subprocesses to reject EPOLL_CTL_ADD with a thread-local seccomp filter after Go's poller is initialized. They verify os.ErrNoDeadline, nil owners, and descriptor cleanup. The same filter loader supports Netlink's setup-failure fixtures; no parent thread receives these restrictions. The fanotify namespace suite reuses this filter for both notification and content groups after confirming each class opens successfully; it requires initial-user-namespace CAP_SYS_ADMIN.

Netlink's ordinary-user tests use read-only controller/route queries, parser fixtures, and test-owned sockets. Kernel socket filters on those sockets exercise missing ACKs and malformed framing; independently queued kernel replies exercise sequence/echo mismatches. Bounded subprocesses confine descriptor exhaustion and thread-local seccomp denial of individual setup operations, checking errno and cleanup without changing parent or host policy.

Run `make specs package=netlink profile=namespaces required=true` for kernel multicast, dump ordering/interruption, and receive-queue overflow fixtures, using the [isolated container command](#netlink-isolation) when the agent shell denies namespace creation. Each fixture reexecutes in mapped user/network namespaces; only the child changes loopback state or adds private addresses. The dump fixtures pause between sending and receiving while a separate connection changes the address generation. The overflow fixture reduces only its own socket receive buffer and generates 32 private loopback changes; it verifies ENOBUFS and a separate recovery dump without changing host limits. Rootless profile runs skip these unselected fixtures; required namespace runs fail if child creation/mapping is unavailable.

Select `package=netlink/route` for typed routing coverage. The rootless suite performs read-only listing, public decoder fixtures/fuzz seeds, validation, deadlines, and lifetime checks. Its selected namespace fixtures use the same bounded child harness for dummy-link lifecycle, IPv4/IPv6 addresses, extended routing tables and gateway replacement, and multicast changes. Only those private network namespaces receive mutations. Native constants, wire construction, errno aliases, and independent kernel observations live in `internal/test`; assertions remain in the package scenarios.

## Profiles and prerequisites

| Setting | Meaning |
| --- | --- |
| `profile=rootless` | Default; tests intended for ordinary users. Namespace transitions, mount, and descriptor-based fanotify success tests require the namespace profile. |
| `profile=namespaces` | Also request namespace creation/mapping, isolated integration, and security privilege transitions. The latter require initial NoNewPrivs=0 and effective CAP_SYS_ADMIN; fanotify requires initial-user-namespace CAP_SYS_ADMIN. |
| `profile=cgroup` | Select live cgroup mutations inside an explicitly supplied delegated subtree; namespace creation is not required. |
| `delegation=/absolute/path` | Supply a disposable cgroup v2 subtree for `profile=cgroup`. Exported as `GO_LINUX_TEST_CGROUP`; discovery only reads its identity/controller files. |
| `required=true` | Fail known unavailable selected prerequisites; the default `false` permits precise skips. Unexpected errors fail in either mode. |
| `arch=amd64` or `arch=arm64` | Require both the Go binary and host machine to match; omit for an unselected native run. |
| `kernel=supported` | Default; Linux 7.0 or later. Use `7.0` for the exact baseline major/minor or `newer` for a later kernel. Mismatches always fail. |

Pass these Make variables explicitly; the Makefile exports the corresponding `GO_LINUX_TEST_*` settings. Invalid values fail before probing. For example:

```sh
make test-environment profile=namespaces required=true arch=arm64 kernel=7.0
package=mount make specs profile=namespaces required=true arch=arm64
```

Environment discovery reports actual Go/kernel/architecture, UID/capabilities, security settings, and namespace prerequisites. Namespace creation alone does not prove mount operations work, and UID 0 does not establish ordinary-user coverage. Rootless runs may skip mount success scenarios; the separate required mount lane covers them. A skip is not runtime verification, and a facility error such as EPERM must not become a blanket skip.

## Rootless container verification

The native rootless CI jobs use machine executors to control the container syscall profile. A managed Docker executor can return ENOSYS for baseline-supported syscalls, including the xattr-at family, even when its host runs Linux 7.0. Changing the Go image does not change that outer filter.

Use a native Linux Docker host, a nonroot invoking user, and the Go image from [.circleci/config.yml](../.circleci/config.yml):

```sh
make verify-rootless-container image=alexfalkowski/go:5.24 arch=amd64 package=xattr
```

Omit `package` for the complete rootless suite used by CI. The launcher downloads the [Moby default seccomp profile at a pinned revision](https://github.com/moby/profiles/blob/f862455628f78f84c937e967e4a03902fb1dee11/seccomp/default.json), checks its SHA-256 digest, and passes it explicitly to Docker. This allowlist includes getxattrat, setxattrat, listxattrat, and removexattrat. The host Docker runtime/libseccomp must recognize those syscalls. Profile download or checksum failures stop verification; the launcher does not fall back to an unconfined container.

A root setup process remaps the image's `circleci` user and home to the invoking UID. Docker's init remains root at PID 1, providing the different-UID target required by signal-permission tests; its KILL capability permits forwarding signals to the nonroot child. All checks run with the invoking UID/GID, no supplementary groups, and empty capability sets; no-new-privileges is enabled from startup. The checkout is mounted separately at `/work`, so account setup does not change its ownership. The Docker bind mount must preserve the test UID/GID's write access; rootless-daemon UID mappings require corresponding checkout ownership. `make verify-rootless` refreshes dependencies, records the environment, and runs lint, script lint, security checks, vet, tests with race detection, and coverage. Modules, build artifacts, and tool caches are disposable container state. Reports are bind-mounted to the checked-in `test/reports/` directory. The local verification command does not upload coverage; `make codecov-upload-container image=<tag>` remains available for an explicit upload of an existing `final.cov` from the Go image.

## Netlink isolation

Netlink's isolated fixtures need permitted mapped user/network namespaces and network administration inside those private namespaces. They do not require fanotify's initial-user-namespace CAP_SYS_ADMIN. Use a native Linux Docker host and the Go image from CI:

```sh
make verify-netlink-container image=alexfalkowski/go:5.24 arch=amd64
```

The same launcher runs locally and in `build-netlink` on native amd64/arm64. It uses the existing privileged-container setup, refreshes dependencies, records `environment.json`, and runs `make verify-netlink`. Dependency setup and image acquisition may require network/registry access and a writable checkout/vendor directory. Use a writable disposable source copy if existing vendor ownership prevents refresh. Rootless Docker works in the observed local configuration; prerequisite and operation failures remain failures on other hosts.

`verify-netlink` records prerequisites and selects `profile=namespaces required=true` for `netlink` and `netlink/route` in one invocation of the shared `specs` harness. Each fixture creates further private namespaces before changing loopback, dummy links, addresses, or routes. Both packages appear in the standard `specs.json`, `specs.xml`, and `profile.cov` files directly under `test/reports/`, alongside `environment.json`. The test target leaves coverage merging to the separate CI coverage job.

With the configured tools and permitted namespaces available directly, use `make verify-netlink arch=amd64`. To require exact-baseline evidence, add `kernel=7.0` to either invocation. Both the rootless `build` jobs and `build-netlink` jobs require this setting in CI. A newer host fails rather than being accepted as Linux 7.0 evidence; a container image does not select the host kernel. Use native amd64 and arm64 runners rather than interpreting emulation as native coverage.

The dump fixtures verify the actual kernel interruption marker independently, then use controlled kernel reply queues and socket filtering to verify ACK-before-DONE ordering, interruption draining, and subsequent connection reuse through Conn.Dump. These controlled conditions do not establish naturally occurring malformed kernel replies. Malformed routing records and controls remain covered through public parsers/fuzzing or explicit source review where the kernel does not emit them. Sequence wrap would require roughly 2^32 exchanges. No production injection hooks or fake-kernel fixtures substitute for missing live evidence; the remaining limits stay tracked under R01.

## Namespace verification

The namespace package's ordinary-user suite covers all eight handle types, identity, adoption, ownership, lifetime, concurrency, errors, and examples. Thread transitions run only in bounded subprocesses selected by the namespace profile. Run the same isolated suite locally and in CI with the configured Go image:

```sh
make verify-namespace-container image=alexfalkowski/go:5.24 arch=amd64
```

The launcher requires a native Linux Docker host that permits privileged containers and mapped user namespaces. It refreshes dependencies and runs `make verify-namespace`, recording prerequisites and the standard reports directly in `test/reports/`. A writable disposable checkout can be used when dependency ownership prevents refresh. Namespace and capability transition fixtures create private mapped user namespaces before creating or entering further namespaces. Landlock device-node fixtures instead retain initial credentials in private mount-namespace children, because ordinary device creation requires initial-user-namespace CAP_MKNOD. Security privilege fixtures retain the container's starting credentials and change only bounded child processes. Tests verify mount, cgroup, IPC, network, UTS, PID, and time creation; permitted entry; user hierarchy/owner inspection; standard child creation; single-threaded user/time restrictions; and worker-thread cleanup after success, failure, and recovered panic. The startup thread is reserved while tests run so thread-destruction observations target workers rather than Go's permanently parked startup-thread special case. No host namespace is entered or mutated.

The `build-namespace` matrix selects `kernel=7.0` on native amd64 and arm64, and its profiles participate in coverage merging. The launcher runs `namespace`, `file`, `capability`, `seccomp`, and `landlock` in one standard test invocation. File metadata coverage requires a visible `/dev` block inode, exposed by the privileged container. Security privilege cases require initial NoNewPrivs=0 and effective CAP_SYS_ADMIN in the caller's user namespace; selected required runs fail if either is unavailable. With suitable tools and privileges directly available, use `make verify-namespace arch=amd64`; add `kernel=7.0` to require exact-baseline evidence. Rootless runs skip the unselected transition fixtures; `profile=namespaces required=true` fails on missing creation/mapping prerequisites. Once a child starts, failed facility operations always fail the test. Thread creation or capability bits alone are not evidence of entry/creation success. Child assertions execute real operations but their statement counters are not merged into the parent coverage profile.

## Capability verification

Run `make specs package=capability` for ordinary-user inspection, invalid masks, empty-set transitions, and denied operations through the standard race/coverage harness. Every credential mutation runs in a bounded subprocess and stays on a locked goroutine. The test runner's credentials remain unchanged. Procfs thread status provides independent kernel observations alongside typed API assertions.

Positive permitted/effective/inheritable transitions, bounding drops, ambient changes, thread isolation, securebits refusal, and exec transformations run in private mapped user-namespace subprocesses. They share the existing namespace lane and launcher:

```sh
make verify-namespace-container image=alexfalkowski/go:5.24 arch=amd64
```

This runs the packages in the namespace lane with `profile=namespaces required=true`. With the configured tools and permitted namespaces directly available, use `make verify-namespace arch=amd64`. The disposable children need a bounding set containing the tested capabilities, including CAP_CHOWN, CAP_MAC_OVERRIDE, and CAP_BPF, and effective CAP_SETPCAP for bounding/securebits changes. The privileged container provides the intended fixture environment; root or a successful namespace probe alone is not operation evidence. Exec tests change securebits only in children to distinguish ambient inheritance from UID-0 restoration, and execute only the test binary without file capabilities. Rootless runs skip the unselected privileged scenarios; selected required prerequisites and all failures after child startup fail.

Add `kernel=7.0` when collecting exact-baseline evidence and use each native architecture. The existing `build-namespace` matrix requires both, and its coverage partitions include the capability package. Subprocess assertions establish runtime behavior but do not merge their statement counters into the parent coverage profile. Reports stay directly under `test/reports/`; CI retains the results for each native runner.

## Seccomp verification

Run `make specs package=seccomp profile=rootless required=true` through the standard race/coverage harness. Every filter load runs in a bounded subprocess; no main test-runner thread receives restrictions. Rootless fixtures need permitted seccomp filter/action operations, no-new-privileges setup, and procfs thread-status inspection, without capabilities or namespaces. Required operation failures fail the suite. The existing rootless architecture matrix discovers the package automatically; use the [rootless launcher](#rootless-container-verification) with `package=seccomp` for the configured image and syscall profile.

Tests compare actual getpgid outcomes for allowed/denied scalar arguments, instruction branches, all supported actions, stacking, thread-local versus TSYNC scope, a refusing thread's TID, exec inheritance, and native policy-denied calls. Aggregate instruction-limit coverage attempts at most nine maximum-sized filter loads in one child, requires ENOMEM after successful loading, and checks the independent filter count to establish that refusal attached nothing. Fatal KILL_PROCESS and x32 checks require SIGSYS termination; TRAP instead exercises Go's synchronous fatal-signal handler. KILL_THREAD observes only a disposable worker's disappearance. The x32 check applies only on amd64. Procfs supplies independent filter counts and no-new-privileges observations. Construction and ordinary probes execute in the parent; child assertions establish loading behavior without merging child coverage counters. Audit-log delivery, external ptrace handling, and unsupported architecture execution are outside these tests.

The [namespace lane](#namespace-verification) additionally exercises a zero-to-one no-new-privileges transition after dropping capabilities, EACCES rejection with neither authority, capability-authorized loading with the bit unset, and TSYNC propagation to an existing sibling starting with a zero bit. Each successful load must enforce its filter; failed loading must preserve the privilege bit and filter count. Rootless runs explicitly skip these four unselected cases.

Exact-baseline evidence requires the required rootless and namespace suites on native Linux 7.0 amd64 and arm64 runners. A newer host or emulated/compile-only architecture cannot establish this evidence. Standard reports remain directly under `test/reports/`; defensive-path gaps are recorded in [verification limits](verification-limits.md).

## Landlock verification

Run `make specs package=landlock profile=rootless required=true` with the standard race/coverage harness, or select `package=landlock` in the [rootless container launcher](#rootless-container-verification) for the configured Go image and pinned syscall profile. Landlock must be enabled and allowed by the enclosing security policy; rootless scenarios need no capability or namespace. Device-ioctl scenarios also require a usable `/dev/ptmx` and devpts mount. Optional runs skip only an absent/disabled facility, while required runs fail. Unexpected policy denials fail in either mode. ABI 8 is the Linux 7.0 baseline; optional pathname-Unix and UDP enforcement scenarios require ABI 9 and 10 respectively and skip on baseline hosts, even in required mode.

Every restriction, thread-local syscall denial, and descriptor-exhaustion scenario runs in a bounded subprocess. Tests exercise allowed/denied file access, truncation, directory listing, cross-directory Refer, device-ioctl authority captured at open time, FIFO/pathname-socket creation rights, pre-opened file authority, borrowed-rule identity after close/rename, stacking and layer exhaustion, TCP connect/bind, IPC scopes, exec inheritance, and both calling-thread and all-thread enforcement. A divergent sibling domain verifies the kernel's replacement semantics. Optional newer-ABI scenarios verify pathname-Unix and UDP destination enforcement. Other tests cover ABI discovery, input validation, independent rule classes, errno, close-on-exec ownership, temporary-file cleanup, concurrent add/close, and executable examples. No parent thread or host-wide policy is changed.

Coverage children receive a private output directory, allowed only for the policy's handled filesystem rights, so all-thread and inherited restrictions permit Go's coverage writer to finish. Nested exec fixtures explicitly retain that same reporting directory. Behavioral assertions execute in those children; the parent statement profile does not merge their counters. Audit-log delivery is outside the package's promises. Missing defensive-path and platform evidence is recorded in [verification limits](verification-limits.md).

The [namespace lane](#namespace-verification) additionally checks the zero-to-one privilege transition after dropping capabilities, EPERM rejection with neither authority, capability-authorized restriction with the bit unset, and TSYNC propagation to an existing sibling starting with a zero bit. File access verifies enforcement independently of privilege observations. The same lane selects character/block-device creation on test-owned private tmpfs mounts. Those fixtures need initial-user-namespace CAP_MKNOD, applicable CAP_SYS_ADMIN, and permitted device policy; mapped user namespaces and privileged rootless Docker cannot supply the initial privilege. Positive controls must succeed before restriction, and opposite creation rights must not grant the requested inode type. Device nodes are never opened. Rootless runs explicitly skip the four privilege and two device-node cases.

The required `build` and `build-namespace` matrices cover Landlock's rootless, credential-transition, and device-node scenarios. Exact-baseline acceptance requires native Linux 7.0 amd64 and arm64 runs; ABI support on a newer host does not establish that evidence. On ABI 8 the optional-right negotiation tests must reject requests for ABI 9/10 rights without returning a ruleset. Retain the environment and standard reports directly under `test/reports/`.

## Cgroup verification

The rootless `cgroup` suite exercises captured native-format fixtures, read-only current-group operations, ownership/errors, descriptor exhaustion, watcher deadlines/concurrent close, and executable examples. Event-dependent current-group tests skip only when `cgroup.events` is absent at the real hierarchy root; other inspection tests remain enabled. Selecting `profile=cgroup` makes event-dependent tests use a test-owned child of the supplied delegation, so that profile requires event coverage regardless of the runner's current membership. Mutation tests require an explicit disposable delegation; neither directory ownership, UID 0, nor a namespace probe establishes that it is usable.

```sh
make verify-cgroup delegation=/absolute/delegated/subtree arch=amd64
```

Use the configured Go image's toolchain on a native Linux 7.0+ runner with a writable v2 mount. The delegator must grant directory creation/removal and the documented membership/subtree-control permissions and enable `cpu memory pids` for children. Run the test process in a leaf below the same delegation (or with the necessary common-ancestor migration permission), so its spawned children can move into test groups. Do not supply a shared production workload group. The test suite creates uniquely named children and changes only those children; it never changes the supplied parent's controllers, limits, permissions, or membership, and never migrates the test runner. Test child processes are bounded and reaped before directory cleanup.

Enforcement scenarios keep the test runner outside each limited leaf and release a workload only after its startup handshake and explicit migration. A bounded busy child must increment CPU throttling counters. A 64-MiB anonymous mapping supplies new charges for `memory.high` and `memory.max` boundary events; the high-limit child must finish without an OOM kill. The max-limit test permits reclamation or an OOM kill, requiring SIGKILL and a matching `oom_kill` increment for a killed child, and does not force a particular swap-dependent outcome. A shell attempts one fork under a zero PID limit, then succeeds after reset to `Max`. Workloads use the existing bounded subprocess cleanup, `/bin/sh`, and `/bin/true`; only test-owned children receive limits.

`verify-cgroup` records `environment.json` and runs `package=cgroup profile=cgroup required=true` through the standard race/coverage harness. It covers child lifecycle, independently owned handles, CPU/memory/PIDs limits, unavailable controllers, atomic controller changes and refusal, whole-process migration, populated notifications, watched-group removal while its handle remains open, and cleanup after descriptor exhaustion during creation. Missing explicit delegation fails required coverage; invalid paths, read-only mounts, and facility failures fail once a subtree is supplied. Optional rootless runs skip the unselected live scenarios. Read-only discovery is not proof of mutation success. Add `kernel=7.0` and the native architecture when collecting baseline evidence; retain the standard reports directly under `test/reports/`.

The `build-cgroup` CI matrix uses the same container launcher available locally on a native Linux Docker host:

```sh
make verify-cgroup-container image=alexfalkowski/go:5.24 arch=amd64
```

The launcher requires permitted privileged containers, cgroup v2, and CPU, memory, and PIDs controllers delegated to Docker containers. It explicitly selects a private cgroup namespace and checks that the v2 membership starts at its root, including on hybrid hosts with unrelated v1 entries. A fresh namespace-rooted cgroup2 mount exposes only the container's subtree; no host cgroup directory is bind-mounted. The launcher moves itself into a separate runner leaf, enables the three controllers for a sibling delegation, refreshes dependencies, and invokes `make verify-cgroup`. This supplies common-ancestor migration permission without changing host workload membership, controller configuration, or limits. Docker removes the disposable subtree when the container exits. Missing controllers, mount permissions, or delegation fail the run without a host-hierarchy fallback. See the [Linux 7.0 cgroup namespace rules](https://docs.kernel.org/7.0/admin-guide/cgroup-v2.html#interaction-with-other-namespaces).

Use the configured Go image and a writable checkout/vendor directory; dependency setup and image acquisition may need network/registry access. A writable disposable source copy can avoid existing vendor ownership restrictions. Reports remain directly in `test/reports/`. CI selects `kernel=7.0` on native amd64 and arm64 and stages each profile as `cgroup-<arch>` for the required coverage merge. The rootless lane retains fixture/read-only coverage. The environment matrix below records observed runs; the required CI jobs validate the native baseline during PR validation.

## Mount verification

Use a native Linux host with rootful Docker, initial-user-namespace `CAP_SYS_ADMIN`, kernel support for XFS, and usable loop devices. Select the Go image from [.circleci/config.yml](../.circleci/config.yml) and the host architecture.

```sh
make verify-mount-container image=alexfalkowski/go:5.27 arch=amd64
```

The launcher uses the image's `mkfs.xfs` and util-linux `mount`, refreshes Go dependencies, and runs `make verify-mount`. The target records `environment.json` and runs the mount package's required namespace suite. The tmpfs fixtures use private user and mount namespaces, including the inotify scenario that observes Unmount followed by Ignored. The reflink fixture retains initial-user-namespace privilege in a private mount namespace with private propagation. It formats and loop-mounts a disposable sparse XFS image, clones test-owned files with `FICLONE`, and checks physical mappings and sharing with `FIEMAP` before and after each unshare mode. The fixture unmounts the image and uses loop autoclear. Required prerequisite and operation failures fail the command. Reports are bind-mounted back to `test/reports/`. Use a writable disposable source copy when dependency ownership prevents refresh.

With `mkfs.xfs` and util-linux `mount` installed directly, `make verify-mount arch=amd64` runs the same discovery and mount suite. Add `kernel=7.0` to require the exact kernel baseline. CircleCI selects it for both native architectures.

CircleCI also selects the ext4 write-zeroes test with `write-zeroes=true`. Use this option on a disposable native runner with a loadable, initially unloaded `scsi_debug` module, root or passwordless `sudo`, and rootful Docker.

```sh
make verify-mount-container image=alexfalkowski/go:5.27 arch=amd64 kernel=7.0 write-zeroes=true
```

The launcher loads `scsi_debug` with one RAM-backed disk and enables WRITE SAME with unmap. It unloads the module when the container exits. The test finds the disk under the `scsi_debug` driver in sysfs and checks its queue's `write_zeroes_unmap_max_bytes` before formatting it with the image's `mkfs.ext4` in a private mount namespace. It verifies size and contents, partial-block boundaries, written extents and mapping reuse after overwrite, and an unwritten extent from ordinary zero-range. A selected test fails if the fixture cannot run. Plain `make verify-mount` selects the mount and XFS tests.

The mount lane also exercises `file.SyncFS` through regular file and directory handles on a disposable XFS image. Both calls must succeed and leave their handles usable. The fixture checks kernel execution and handle behavior. Crash recovery and persistence after power loss need separate evidence.

## Fanotify verification

Use a native Linux host with a rootful Docker daemon and initial-user-namespace `CAP_SYS_ADMIN`. The host kernel must provide `CONFIG_FANOTIFY` and `CONFIG_FANOTIFY_ACCESS_PERMISSIONS`. Rootless Docker cannot supply the required initial-namespace privilege, including with `--privileged`; the launcher rejects that environment before running setup.

```sh
make verify-fanotify-container image=alexfalkowski/go:5.24 arch=amd64
```

The launcher uses the configured Go image and runs dependency setup followed by `make verify-fanotify`. That target records the environment and runs `package=fanotify profile=namespaces required=true` through the ordinary race/coverage harness. Each live fixture reexecutes in a private mount namespace without creating a user namespace, preserving the required initial-namespace privilege. It makes mount propagation private and uses only test-owned files and private tmpfs instances; no host files or mounts receive marks. Tests verify notification files, inode/mount/filesystem marks, permission responses and shutdown, iterator cleanup, deadlines, and concurrent close. Examples run in the same isolated fixtures. The `build-fanotify` CI matrix requires these operations on native amd64 and arm64; capabilities and successful namespace creation alone do not count as fanotify evidence.

With the configured tools installed on a suitable privileged Linux runner, use `make verify-fanotify arch=amd64` directly. From a shell with sudo access, `sudo env "PATH=$PATH" make verify-fanotify arch=amd64` retains access to user-installed Go, Ruby, and gotestsum tools. Ordinary rootless package tests execute parser, cleanup, and invalid-input scenarios while skipping the unselected live fixtures. Selecting `profile=namespaces required=true` fails on missing privilege; errors after entering the fixture always fail rather than becoming blanket skips. A failed required run is not runtime coverage.

## Clock-changing tests

> [!WARNING]
> Run these tests only in a dedicated disposable VM with time synchronization disabled. They change the Docker host VM's CLOCK_REALTIME; containers and time namespaces do not isolate that clock. Never run them on a shared host.

Inside that VM, using its native architecture and the configured Go image:

```sh
sudo timedatectl set-ntp false
make verify-timerfd-container image=alexfalkowski/go:5.24 arch=amd64 clock_change=true
```

The explicit acknowledgment is required before Docker starts. The launcher runs dependency setup and `make verify-timerfd`, selecting only timerfd with the `clockchange` build tag, required prerequisites, vet, race detection, and reports. Missing clock-setting permission fails. The tagged suite includes typed epoll registration during forward/backward clock cancellation, ECANCELED reads without fabricated expirations, and readiness cleared after consumption. Cleanup restores wall time using monotonic elapsed time, but abrupt termination can prevent restoration; discard the VM afterwards.

With tools installed directly, use `make verify-timerfd arch=amd64 clock_change=true`. Ordinary `make specs` does not enable clock-changing tests, including when run as root. Both privileged verification targets retain `environment.json` with their test reports.

## File verification

Run `make specs package=file profile=rootless required=true` for ordinary file operations and metadata. The NoDump scenario sets and clears only a test-owned temporary file's flag, checking both the attribute value and its validity mask. Its temporary filesystem must support the inode-flag ioctls and report NoDump support through statx.

Allocation tests use disposable files and compare their size, contents, and allocated blocks. If the default temporary directory is on tmpfs, set `TMPDIR` to a writable directory on a filesystem that supports zero-range, collapse, and insert at the block alignment used by the fixtures. For example, from a checkout on extent-based ext4 without `bigalloc`, run `TMPDIR="$PWD/test" make specs package=file profile=rootless required=true`. Optional runs on tmpfs skip those specific scenarios with a prerequisite message. Required runs fail if the selected temporary filesystem cannot execute the requested operation.

The rootless suite checks all six `Fadvise` hints, `Readahead` on a readable file, and `Fdatasync` after a log write. The tests verify range validation, kernel errors, and borrowed-file offsets. Cache policy and residency can vary with the filesystem and workload. The [mount lane](#mount-verification) executes filesystem-wide synchronization.

The same suite exercises `Flock` on test-owned local files in bounded child processes. It checks shared acquisition, exclusive contention, a blocking waiter released by explicit unlock, and release on child exit. It also checks duplicate references and a contended shared-to-exclusive conversion. Use the existing [rootless launcher](#rootless-container-verification) to exercise the pinned syscall profile without capabilities.

The [namespace lane](#namespace-verification) additionally selects live block-device metadata. With the configured tools and a visible `/dev` block inode, use `make specs package=file profile=namespaces required=true`. The test obtains a path-only handle, then compares the translated block-device mode and represented-device numbers with an independent kernel query. It performs no device data I/O or device creation. Ordinary rootless runs leave this fixture unselected; selected required runs fail if no block inode is visible. The privileged namespace container exposes the host's existing device inodes and supplies the CI environment for this scenario.

## Sysfs verification

Run `make specs package=sysfs profile=rootless required=true` through the standard race/coverage harness. Fixtures use ordinary temporary directories with class symlinks; no device nodes, host mutations, capabilities, or namespace creation are required. Coverage includes partitions, missing and malformed attributes, exact byte preservation and size limits, checked units and numeric widths, path validation, device disappearance/replacement, concurrency, and descriptor cleanup. Shared fixture helpers are in `internal/test`; assertions remain beside the public API scenarios.

Live read-only tests discover the available inventory rather than assuming particular block or interface names. They compare network index/MTU with the standard library, independently resolve block major/minor identities through `/sys/dev/block`, and check loopback's unavailable speed returns the kernel's EINVAL rather than silently becoming zero. A host with no block entries has no live block scenarios; fixtures still cover block behavior. The network checks require sysfs to expose interfaces from the current network namespace, including loopback. Permission-error fixtures require an ordinary user without DAC override; selected required runs fail rather than skip that prerequisite.

The existing rootless architecture matrix discovers the package automatically. Use the [rootless launcher](#rootless-container-verification) with `package=sysfs` for the configured image and syscall profile. The required CI matrix validates native Linux 7.0 amd64 and arm64; a newer local kernel does not establish baseline evidence.
