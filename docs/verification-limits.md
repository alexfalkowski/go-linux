# Verification limits

These are known limits of the library's execution evidence. Source review and parser fixtures do not establish live-kernel execution, and passing required CI lanes does not exercise every defensive path. [Verification](verification.md) owns supported commands, isolation prerequisites, reports, and observed environments.

Retain these limits where supported public/kernel scenarios cannot reproduce a path without production injection hooks. A later verification run may resolve a limit when it records the actual operation and required environment; do not treat privilege observations, compilation, or a newer kernel as equivalent evidence.

| Scope | Missing evidence | Evidence boundary or prerequisite |
| --- | --- | --- |
| `sysfs` defensive paths | Rare working-directory resolution, root revalidation, and post-open metadata failures remain source-reviewed. | Retain these limits where supported public/kernel scenarios cannot reproduce them without production injection hooks. Fixtures establish class symlinks, partitions, malformed/oversized input, missing attributes, units, replacement, and cleanup; live reads establish available device identity, network values, and an unavailable attribute's kernel read errno. |
| `landlock` defensive paths | Rare allocation/cleanup failures remain source-reviewed. | Retain explicit limits where execution is unavailable without production injection hooks. Audit-log delivery and a complete sandbox are outside the package's promises. |
| `seccomp` defensive paths | Direct execution remains absent for the nonnative audit-architecture kill branch, aggregate filter-tree exhaustion, and rare kernel allocation failures. The amd64 x32 kill guard is exercised independently. | Reconcile using bounded public/kernel scenarios on appropriate disposable runners; retain source-reviewed limits where unavailable without production injection hooks. Audit-log delivery and external ptrace management are outside the package's enforcement promises. |
| `cgroup` defensive paths | Event overflow and rare metadata/close errors remain source-reviewed. | Reconcile using bounded public/kernel scenarios in an explicit disposable delegation; retain source-reviewed limits where execution is not feasible without production injection hooks. |
| `namespace` defensive paths | Direct execution remains absent for rare descriptor metadata/flag/cleanup failures, namespace allocation failures other than descriptor exhaustion, and unknown kernel namespace types. Startup-thread permanent parking remains source-reviewed; tests reserve it and execute worker-thread destruction. | Retain these limits where supported public/kernel scenarios cannot reproduce them without production injection hooks. Actual namespace creation/entry, refused transitions, acquisition/related-ioctl EMFILE cleanup, FIFO rejection, child inheritance, and recovered-panic cleanup are exercised. |
| `netlink/route` defensive live decoding | Malformed routing payloads, unexpected dump message types/families, and unsupported notification types are covered through public decoder fixtures/fuzzing or source review, without live exchange execution of those kernel responses. | Retain these limits where the real kernel does not emit such records; use supported public/kernel scenarios if reproducible, without production injection hooks or treating parser fixtures as live exchange evidence. |
| `netlink` defensive paths | Live exchange coverage remains absent for invalid recipient-port headers, malformed inner ACK/DONE bodies, NOOP/OVERRUN/reserved controls, interruption first signalled by a nonterminal success ACK, and uint32 sequence wrap. Parser tests cover malformed controls independently. | Real-kernel fixtures now execute malformed framing, sequence/echo mismatches, ACK-before-DONE ordering, interrupted-dump draining/reuse, receive-timeout cleanup, descriptor exhaustion, and bind/ACK-option/strict-check/address-inspection failures. The remaining controls are not emitted by the observed kernel scenarios; wrap requires roughly 2^32 public exchanges. Retain these source-reviewed limits without production injection hooks or treating parser fixtures as live exchange evidence. |
| `socket` defensive paths | Direct execution remains absent for malformed kernel address/control headers, interrupted syscall retries, and rare allocation/cleanup failures. | Reconcile using supported public/kernel scenarios and appropriate isolated runners; retain source-reviewed limits where execution is not feasible without production injection hooks. |
| `xattr` defensive read paths | Concurrent value and list mutation runs do not deterministically establish ERANGE retry/exhaustion, the oversized query guard, or malformed kernel-list rejection. | Reconcile using supported public/kernel scenarios where reproducible; retain source-reviewed limits rather than adding production injection hooks. |
| Other defensive paths | Direct execution remains absent for defensive timerfd zero-byte conversion; file block-device conversion, remote synchronization, automount, and positive attributes other than MountRoot; oversized/malformed mount diagnostics; and rare acquisition, response, cleanup, or partial-application failures. | Reconcile during PR validation using supported public/kernel scenarios and suitable isolated runners; retain explicit limits where execution is not feasible. |
| `pidfd` positive core-dump status | Actual CLD_DUMPED and `CoreDump=true` on the Linux 7.0 arm64 target | A runner whose existing core policy produces CLD_DUMPED for the test-owned child. The current test compares with nonconsuming kernel status; CLD_KILLED verifies only the false flag. Do not change host core policy to force this case. |
